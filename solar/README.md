# Solar

A HyperFrames + Three.js animation of a stylized 3D solar system with Edge TTS narration in English, Chinese, Japanese, and Korean.

## Scripts

```bash
npm install
npm run voiceover
npm run sync:validate
npm run dev
npm run check
```

The composition IDs are `solar-en`, `solar-zh`, `solar-ja`, and `solar-ko`.
Render one language with `npm run render:en`, `npm run render:zh`,
`npm run render:ja`, or `npm run render:ko`.
The narration sources are `public/voiceover/narration.{lang}.txt`. Generated MP3
files are not committed. `npm run voiceover` generates segmented Edge TTS audio,
merges each language into its final MP3, writes cue JS/JSON from measured segment
durations, and updates composition durations. `npm run check` validates the sync
data and runs HyperFrames lint.

Tags use the common release workflow. A tag such as `solar-1.0.0-zh` resolves
to this directory and runs `npm run render:zh`, releasing only the selected
variant. Solar release tags must include a variant.

The current CI voices are:

- English: `en-US-AriaNeural`
- Chinese: `zh-CN-XiaoxiaoNeural`
- Japanese: `ja-JP-NanamiNeural`
- Korean: `ko-KR-SunHiNeural`

Typography is loaded from the Google Noto repository through jsDelivr at preview
and render time:

- English: `Noto Sans`
- Chinese: `Noto Sans SC`
- Japanese: `Noto Sans JP`
- Korean: `Noto Sans KR`

Network access to `cdn.jsdelivr.net` is required. Font binaries are not stored in
this repository.

Install the pinned generator before running the local pipeline:

```bash
python -m pip install edge-tts==7.2.7
npm run voiceover
npm run check
```

Audio/video timing, measured durations, and validation rules are documented in
[`../AUDIO_VIDEO_SYNC.md`](../AUDIO_VIDEO_SYNC.md).

## Remotion port (`src/`, alongside the HyperFrames originals)

The original HyperFrames compositions (`compositions/*.html`,
`public/solar-scene.js`, `public/solar-composition.js`) are untouched. The
Remotion port lives in `src/` + `remotion.config.ts` + `tsconfig.json` and
reuses the generated `public/voiceover/cues.*.json` as its timing source.

| Composition | Locale | Duration | Frames (30fps) |
|-------------|--------|----------|----------------|
| `solar-en`  | en     | 75.044s  | 2251           |
| `solar-zh`  | zh     | 90.548s  | 2716           |
| `solar-ja`  | ja     | 113.636s | 3409           |
| `solar-ko`  | ko     | 108.068s | 3242           |

Durations come from the cue JSON `compositionDuration` (audio + 0.5s
`END_PADDING`), so regenerating the voiceover re-times every composition
with no manual edits. One `Solar` component serves all locales via its
`locale` prop; there are no forked per-locale files.

```bash
npm run dev            # remotion studio
npm run check          # tsc --noEmit
npm run render:en      # + :zh / :ja / :ko per-locale MP4s
```

Voiceover MP3s (`public/voiceover/solar-system-{en,zh,ja,ko}.mp3`) are still
generated by `npm run voiceover` and are not committed; renders need them
on disk.

Frame-pure 3D: `src/SolarScene.tsx` copies the pure scene builders from
`public/solar-scene.js` verbatim (planet table, seeded RNG, canvas
textures, orbit rings, star fields, camera path) but replaces the stateful
per-frame lerp smoothing (planet scale, halo size/opacity, emissive
intensity) with direct closed-form `f(frame)` assignment, and renders with
plain `three` (`WebGLRenderer` driven by `useCurrentFrame`, one render per
frame, `delayRender`-gated). Deliberately no `@react-three/fiber` /
`@remotion/three`: that stack mounts cleanly but presents black frames in
headless renderers (verified). No GSAP clock, no `window.__timelines`, no
render-time fetch, no per-frame DOM queries. Cue overlays are per-cue
`Sequence`s with `interpolate()` fade + y-slide (cubic-out enter ≈
power3.out, quad-in exit ≈ power2.in).

Headless/CI WebGL: `remotion.config.ts` sets `setChromiumOpenGlRenderer('swangle')`
so `chrome-headless-shell` renders through SwiftShader ANGLE. The default
`'angle'` fails with `Error creating WebGL context` on GPU-less machines;
do not override with `--gl=swiftshader` (still black).
